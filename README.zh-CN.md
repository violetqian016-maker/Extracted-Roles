# Extracted Roles — 本科研究数据集

这是 **Ruiyi（Violet）Qian 在复旦大学本科研究期间构建的角色对话数据集**，用于研究角色语言特征与大语言模型的角色扮演生成。项目将影视台词整理为可分析、可用于实验的结构化资源，包含 **16 部作品、96 份角色台词文件、550,628 条台词和 174,000 对提问与回复**，并配有角色档案及词汇表。

[English](README.md) · [数据结构](docs/DATASET.md) · [已知问题](docs/KNOWN_ISSUES.md)

**毕业论文：**《促进动态角色词表构建的高质量英文角色扮演数据集》／*High-Quality English Role-Playing Datasets Facilitating Dynamic Role Vocabulary Construction*。2026 年 5 月完成，指导教师：纪焘。

## 我的研究贡献

本科论文的核心是面向动态词表增强角色扮演的**数据构建与验证框架**，包括三项主要贡献：

1. **设计双输出数据构建框架。** 将角色台词语料用于动态词表提取，将单轮提问—回复种子用于监督微调，明确区分两类任务的数据要求。实现流程覆盖异构剧本解析、文本清洗、说话人归一化、角色抽取、相邻轮次配对及辅助档案构建。论文的解析审计中，稳健解析器从同一批 587,222 行原始文本中抽取 415,968 行对话，严格解析器则为 314,643 行（§4.2.2）。
2. **设计适配两类数据目标的平衡策略。** 台词语料保留角色语言证据；训练种子结合质量筛选和角色级软上限，控制头部角色的样本占比，并保留达到可用门槛的低资源角色。论文记载最终每个角色包含 **1,025–2,000 对样本**（§4.2.6、表 5）。
3. **建立规则化验证与词汇审计流程。** 检查样本完整性、说话人一致性、来源记录、重复 ID 和格式残留，论文最终六项结构检查均未发现对应错误（表 7）。短语匹配审计显示，**82.92% 的目标回复**至少命中一个对应角色词表短语，平均每条回复命中 **2.38 次**（表 6）。

研究贡献在于面向 DVA 的数据框架及其验证。动态词表算法本身并非本文新提出；角色档案作为辅助元数据，细粒度语言证据主要来自剧本台词。

## 数据集的研究意义

研究关注模型如何保留角色可识别的语言习惯。为此，数据既需要提供角色常用词语与短语的提取依据，也需要提供角色在对话中的回应实例。

| 数据资源 | 研究用途 |
| --- | --- |
| 角色台词 | 为动态角色词表提取提供词汇、惯用表达和短语证据 |
| 提问与回复种子 | 为监督微调提供局部对话输入与目标角色回复 |
| 角色词汇表 | 支持词汇条件生成和短语层面的分析 |
| 角色档案 | 为角色条件控制提供辅助身份与背景信息 |
| 来源及质量元数据 | 支持样本检查、过滤，以及平衡和恢复策略分析 |

双输出设计让同一目标角色集合同时服务于词汇分析和对话监督；角色级平衡减少极端数据极化；元数据则让筛选决策可检查。论文覆盖 **16 部作品、96 个目标角色**，当前发布中的角色档案仍有待复核的身份问题，详见已知问题。

## 论文报告的实验结果

论文 §5.6 在相同基础模型与配置下，对比基线与加入角色动态词表的生成设置。

| 指标 | 基线 | DVA 增强 |
| --- | ---: | ---: |
| ROUGE-L | 6.097 | 8.734 |
| 479 次有效比较中的获胜次数 | 155（32.36%） | **309（64.51%）** |
| Diversity | 0.8787 | 0.7648 |

共尝试 480 条测试样本，其中 479 条获得完整评分，平局 15 次（3.13%）。结果为所测设置下的词汇对齐和成对偏好改善提供初步证据；同时，多样性下降、重复短语增加，上下文相关性和角色一致性并非始终改善。该实验不能单独证明训练种子微调造成了上述提升。

以上数字来自论文表 9–10，当前仓库未包含复现所需的完整实验程序及原始评分。详见 [研究背景与依据](docs/RESEARCH.md)。

## 本地使用

需要 Git 和 Python 3.10 及以上版本，无需安装第三方 Python 依赖。

```bash
git clone https://github.com/violetqian016-maker/Extracted-Roles.git
cd Extracted-Roles
python3 scripts/dataset.py validate
python3 scripts/dataset.py catalog --check
python3 -m unittest discover -s tests -v
```

原始数据目录及文件名保持不变。不同目录的作品名和角色名不完全一致，不能仅凭字符串直接关联。`docs/catalog.json` 提供全部文件的路径、条数、大小和 SHA-256 摘要。

## 校验范围

工具检查 JSON 格式、主要字段类型、对话是否为两轮、文本是否为空、目标角色与文件名是否一致、字数总和，以及跨文件对话 ID 是否重复。GitHub Actions 自动运行回归测试和目录索引检查。

格式通过不代表台词归属、剧情事实和上下文已经人工核实。部分保留样本带有短句或恢复标记；源脚本路径虽出现在数据中，对应源文件和提取程序并未收录。
